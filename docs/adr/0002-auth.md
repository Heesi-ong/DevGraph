# ADR 0002: 인증 — 짧은 Access JWT + Family 기반 Refresh Rotation

## 상태
승인됨 (설계서 v1.4 §17.2)

## 컨텍스트
개인 Workspace 격리와 다중 기기 세션을 지원하면서, stateless Access Token의 확장성과 탈취 대응력을
함께 확보해야 한다.

## 결정
- Access JWT(10~15분, 무상태)와 회전형 Refresh Token(7~30일)을 함께 쓴다.
- Refresh Token의 rotation 이력(`auth_sessions`)과 안정적인 기기 세션 식별자(`auth_session_families`)를
  분리한다. Access JWT의 `sid` claim은 rotation에도 바뀌지 않는 `token_family_id`를 가리킨다.
- family에는 절대 세션 수명(`absolute_expires_at`, 기본 90일)을 두어 rotation만으로 세션이
  무기한 연장되지 않게 한다.
- 재사용 감지 시 family 전체를 폐기한다.
- 민감 작업(Export, 영구 삭제, 계정 탈퇴)은 별도의 단회성 `reauthToken`(family당 1개, purpose로 범위 제한)을
  요구한다.

## 근거
- Access JWT를 rotation row id에 직접 묶으면 정상적인 refresh 한 번으로 세션이 깨지는 버그가 생긴다 —
  family 테이블을 분리해 이 문제를 근본적으로 없앴다.
- Redis 없이 무상태 Access Token으로 확장성을 확보하고, 즉시 차단이 아니라 짧은 TTL로 위험을 제한한다.

## 결과
- 장점: 다중 기기 세션을 명확히 구분·개별 폐기할 수 있고, 재인증이 필요한 작업의 범위를 purpose/target
  단위로 좁힐 수 있다.
- 단점: family가 방금 폐기돼도 이미 발급된 Access JWT는 남은 TTL(최대 15분)까지 유효하다 — 즉시 차단이
  필요해지면 그때 deny-list를 검토한다(지금은 만들지 않는다).
